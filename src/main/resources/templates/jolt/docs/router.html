Messages are one way to connect the page to Java. The other is to let the page talk to Java the way a website talks to a server: with fetch, forms, htmx hx-get and hx-post and JSON APIs, answered by a Java handler. If you have built a web app before, this will feel familiar. Files are served inside the web view, with no socket. The origin is https://jolt.localhost on Windows and jolt://app on Linux, so use relative URLs.

You can mix this with messages in the same window, and you can skip it entirely if messages are enough.

1. The smallest handler

A RequestHandler gets each request the page makes to its own app and returns an AppResponse, or null to let your files answer:

window.loadResources(AppResources.classpath("ui"), request -> switch (request.path()) {
    case "/hello" -> AppResponse.text("Hello from Java");
    default -> null;                                  // null: let the files answer
});
const text = await (await fetch('/hello')).text();    // "Hello from Java"

index.html, app.js and the rest of your folder are still served as before; only requests your handler answers reach Java.

2. What a request contains

CallGives you
request.method(), request.path()"POST", "/notes/7"
request.param("id")A {id} part of a Router pattern (section 4).
request.queryParams()The ?a=1&b=2 part as a map of lists.
request.formValue("text")A field of a form post (also reads multipart text fields). request.form() gives all of them.
request.bodyText()The body as UTF-8 text, for example a JSON body you parse yourself.
request.header("Accept")One header, or null.
request.isHtmx()Whether htmx sent it.

Everything in a request is input from the page: validate it like you would a web form.

3. What you can answer with

CallResult
AppResponse.html(String)200 with an HTML body (a whole page or a fragment).
AppResponse.text(String)200 with plain text.
AppResponse.status(204)An empty answer with that status.
AppResponse.redirect("/notes")303: the browser then does a GET of that address.
.withStatus(500), .withHeader(name, value)A copy with a different status or one more header.

For JSON, build the response with the constructor. This helper is all you need:

static AppResponse json(Object value) {
    return new AppResponse(200, Map.of("Content-Type", "application/json"),
            new Gson().toJson(value).getBytes(StandardCharsets.UTF_8));
}

4. The Router

A switch on the path gets awkward fast. Router is a RequestHandler that matches method and path for you:

NoteStore store = new NoteStore();         // the class from the tutorial

Router router = Router.create()
    .get("/api/notes", request -> json(store.list()))
    .post("/api/notes", request -> json(store.add(request.formValue("text"))))
    .delete("/api/notes/{id}", request -> {
        store.remove(Integer.parseInt(request.param("id")));
        return AppResponse.status(204);
    })
    .onError((request, error) -> AppResponse.text("Oops: " + error.getMessage()).withStatus(400));

window.loadResources(AppResources.classpath("ui"), router);

The page then reads like any web app:

const notes = await (await fetch('/api/notes')).json();

const response = await fetch('/api/notes', {
  method: 'POST',
  body: new URLSearchParams({ text: 'Buy milk' }),
});
if (response.ok) console.log(await response.json());       // { id: 1, text: "Buy milk" }
else console.log(await response.text());                    // "Oops: A note cannot be empty"

await fetch('/api/notes/1', { method: 'DELETE' });           // 204
  • Patterns: {id} captures one segment, {*rest} the rest. A plain segment beats {id}, which beats {*rest}. A route registered twice with the same shape is rejected when you register it.
  • Methods: get, post, put, patch, delete.
  • A request no route matches falls through to your files. A wrong method on a known path gets 405 with Allow.
  • onError turns an exception from a route into a response. Without it an exception becomes a bare 500 and the details go to the log, never to the page.
  • Register routes before loadResources.

5. Forms and server-rendered pages

You do not need JavaScript at all. A route can build the whole page as HTML, and a plain form can post to another route. After a post, answer with a redirect so a reload does not send the form again:

Router router = Router.create()
    .get("/notes", request -> {
        String items = store.list().stream()
                .map(n -> "<li>" + escape(n.text()) + "</li>")
                .collect(Collectors.joining());
        return AppResponse.html("""
                <!doctype html><meta charset="utf-8">
                <ul>%s</ul>
                <form method="post" action="/notes"><input name="text"><button>Add</button></form>
                """.formatted(items));
    })
    .post("/notes", request -> {
        store.add(request.formValue("text"));
        return AppResponse.redirect("/notes");
    });

window.loadResources(AppResources.classpath("ui"), router,
        ResourceOptions.defaults().withStartPath("/notes"));       // open on /notes instead of index.html
Escape user text before putting it into HTML; Jolt cannot do it for you. Here escape replaces &, <, > and ". A note typed as <b>Milk</b> & eggs then shows as typed instead of being treated as markup. Template engines such as Thymeleaf or JTE do this automatically.

With htmx the idea is the same, but the answer is a fragment that htmx swaps into the page: hx-post="/notes" on a form, a route that returns AppResponse.html(renderList()). request.isHtmx() tells you if it was htmx asking, so one route can answer a full page or a fragment. Add the htmx script to your ui folder yourself; Jolt does not depend on it.

6. Groups, filters and errors

When parts of the app need a check before they run, such as a login, use a group with a filter:

Router router = Router.create()
    .get("/notes/{id}", request -> AppResponse.html(pages.note(request.param("id"))))
    .post("/notes", request -> { notes.add(request.formValue("text")); return AppResponse.redirect("/notes"); })
    .group("/admin", admin -> admin
        .before(request -> loggedIn(request) ? null : AppResponse.redirect("/login"))
        .get("/users", request -> AppResponse.html(pages.users())))
    .onError((request, error) -> AppResponse.html(pages.error(error)).withStatus(500));

A before filter returns null to let the request go on, or a response to answer it right there.

7. Threads and safety

  • Handlers run on worker threads, possibly several at once. Keep shared data thread-safe, and use app.dispatch(...) if a handler must touch a window.
  • Keep GET handlers free of side effects. Changes belong in POST, PUT, PATCH or DELETE.
  • You do not need CSRF tokens on this transport; it is only reachable from inside your window. (The loopback fallback below adds them for you.)

8. Uploads

multipart/form-data works with plain forms, fetch and htmx. Read it with request.parts() or request.part(name):

AppRequest.Part file = request.part("document");
if (file != null && !file.filename().isEmpty()) {
    Files.write(uploads.resolve(UUID.randomUUID() + ".bin"), file.content());   // choose the stored name yourself
}

Treat uploaded files as untrusted: filename() and contentType() come from the user's machine. Bodies are held in memory, 8 MB by default (413 above that). Raise the limit with ResourceOptions.defaults().withMaxRequestBytes(...), up to 1 GB.

9. Loopback fallback

The in-process transport needs WebKitGTK 2.40 or newer on Linux. Older systems fall back automatically to a guarded server on 127.0.0.1 with a per-run CSRF token and Origin, Host and Sec-Fetch-Site checks. You can also ask for it, for example to open the app in a normal browser: window.loadResources(resources, handler, 48123). A fixed port also keeps localStorage between runs.
