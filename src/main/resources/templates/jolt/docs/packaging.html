So far you have run your app from an IDE or the command line, which needs Java installed and a long command. jpackage, a tool that ships with the JDK, turns your jars into a double-clickable app that bundles its own Java runtime, so your users do not need Java installed. Because Jolt uses the web view the system already has, there is no browser to bundle either.

1. Collect the jars

Build your app jar and gather it together with its dependencies (Jolt's jars and any libraries you use) in one folder, here target\package. With Maven, the maven-dependency-plugin's copy-dependencies goal does the copying; copy your own jar next to them. Make sure your app jar's manifest has Enable-Native-Access: ALL-UNNAMED or pass the flag as shown below.

2. Build an app image

Point jpackage at the folder:

jpackage --type app-image --name MyApp `
  --input target\package `
  --main-jar my-app.jar --main-class com.example.MyApp `
  --java-options "--enable-native-access=ALL-UNNAMED" `
  --add-modules "java.base,java.logging,jdk.unsupported" `
  --jlink-options "--strip-debug --no-man-pages --no-header-files --compress zip-6" `
  --dest dist
  • --type app-image produces a folder you can run or zip. (Installer types such as exe, msi, deb and rpm are other jpackage types, if you need them.)
  • --java-options is where the native-access flag goes, so users never see the warning.
  • --add-modules lists the Java modules to include. Listing only what you need, instead of the whole JDK, is what keeps the app small.
  • --jlink-options shrinks the bundled runtime further.

That gives an app of about 32 MB, compared with about 120 MB without --add-modules and --jlink-options. Add the modules your own dependencies need: if the packaged app fails with a missing class that works from the IDE, a module is missing from the list. Code signing is up to you.

3. Test the packaged app

Run the result on a machine, or a clean user account, that does not have your development setup. On Windows it needs the WebView2 Runtime (preinstalled on Windows 11); on Linux it needs GTK 3 and WebKitGTK 4.1 (see Getting started). Also check that your app does not depend on files that only exist in your project folder: serve the page with AppResources.classpath(...), not directory(...).

4. In practice

Parsel ships this way: a Windows installer of about 33 MB with its own Java runtime inside, plus a portable zip and Linux packages. There is no bundled browser, because the app uses the web view your system already has.
