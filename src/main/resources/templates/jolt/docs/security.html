A window's page can call everything you register with onMessage, and can ask for files, windows and permissions. So each window has a SecurityPolicy that decides which pages are trusted. The default, SecurityPolicy.standard(), trusts your own content plus origins you list, and blocks the rest. For most apps that is exactly right and you never touch it.

1. The idea in one minute

  • An origin is the scheme, host and port of an address: http://localhost:5173, https://example.com.
  • Content you show with loadHtml or loadResources is yours and is trusted automatically.
  • Everything else is untrusted: a link to another website, a redirect, a frame, a page opened with loadUrl. It is blocked unless you add its origin to the trusted list.
  • Only trusted pages can send messages to onMessage.

That keeps the usual accident from happening: a link in some email or a bug sends your window to a web page you did not write, and that page starts calling your Java functions.

3. Configure it

The two things you will actually do are trust an origin (a dev server, a site you control) and react to blocked links:

WindowOptions.defaults().withSecurity(SecurityPolicy.standard().withTrustedOrigins("http://localhost:5173"));
window.setSecurity(window.security().withLockNavigation(false));       // change it any time
window.onBlocked(event -> openInSystemBrowser(event.url()));           // called after something was blocked

A common one is a mail or chat app where clicking a link should open the user's browser, not navigate your window:

window.onBlocked(event -> {
    if (event.kind() == BlockedEvent.Kind.NAVIGATION || event.kind() == BlockedEvent.Kind.NEW_WINDOW) {
        try {
            app.openExternal(URI.create(event.url()));   // only http, https and mailto are opened
        } catch (IllegalArgumentException ignored) { }
    }
});

BlockedEvent.kind() is one of NAVIGATION, NEW_WINDOW, PERMISSION or MESSAGE, and url() says what was blocked.

4. Rules of thumb

  • loadUrl to another site is blocked unless you trust its origin.
  • Trusting an origin gives that site your handlers. List only sites you control, and still validate every parameter.
  • WebView2 reports which frame sent a message; WebKitGTK does not, so on Linux the check uses the top-level page. If you turn the navigation lock off on Linux, keep the bridge out of frames (the default).
  • In the page, set user-supplied text with textContent, never innerHTML.
  • In Java handlers, treat parameters as untrusted input: check types and ranges, and never build file paths or commands from them without validation.
