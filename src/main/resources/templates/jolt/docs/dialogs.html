A web page cannot open a native "Save as" dialog and never learns a file's path, which is a good thing for security. Jolt lets Java open the operating system's own dialogs, and lets a trusted page ask for a save dialog without ever seeing the path. Available since 0.2.4.

1. From Java

Get the dialogs from the window and ask for what you need:

Dialogs dialogs = window.dialogs();
dialogs.saveFile(FileDialogOptions.defaults()
                .withTitle("Export report").withFileName("report.pdf")
                .withFilters(FileFilter.of("PDF documents", "pdf")))
        .thenAccept(chosen -> chosen.ifPresent(path -> writeReport(path)));   // empty if cancelled

dialogs.openFile(FileDialogOptions.defaults());      // also openFiles(...) and chooseFolder(...)
CallResult
openFileCompletableFuture<Optional<Path>>: one file.
openFilesCompletableFuture<List<Path>>: several files (empty list if cancelled).
saveFileCompletableFuture<Optional<Path>>: where to write.
chooseFolderCompletableFuture<Optional<Path>>: a folder.

Each call returns a CompletableFuture at once, so your code keeps running while the dialog is open. Cancelling gives an empty result, not an error. FileDialogOptions can set the title, the folder it opens in (withInitialDirectory), the suggested file name, and filters. withSize(w, h) asks for a bigger dialog (a request: the system owns it).

2. A button in the page that opens a dialog

The usual way to connect a page button to a dialog is a message. The page asks, Java opens the dialog, writes the file and tells the page what happened:

document.getElementById('export').onclick = () => jolt.postMessage('export');
jolt.onMessage(m => { if (m.startsWith('exported:')) status.textContent = 'Saved ' + m.slice(9); });
window.onMessage(message -> {
    if (!message.equals("export")) return;
    window.dialogs().saveFile(FileDialogOptions.defaults()
                    .withTitle("Export notes").withFileName("notes.txt")
                    .withFilters(FileFilter.of("Text files", "txt")))
            .thenAccept(chosen -> chosen.ifPresent(path -> {
                try {
                    Files.writeString(path, notesAsText());
                    window.postMessage("exported:" + path.getFileName());
                } catch (IOException e) {
                    window.postMessage("error:" + e.getMessage());
                }
            }));
});

The future completes on the UI thread, so keep the work in thenAccept short, or move bigger writes onto another thread as shown on the messaging page. Only the file name goes back to the page, never the full path.

3. Straight from the page

To let the page save a file itself, call window.enableSaveAs() in Java and jolt.saveAs in the page:

const saved = await jolt.saveAs(blobOrBytesOrText, { name: "report.pdf", filters: [{ name: "PDF", extensions: ["pdf"] }] });
// { name, size } or null if cancelled; the page never learns the path
  • The data is written to a temporary file and moved into place when complete.
  • Only trusted origins may use it, and on Linux the page must come from loadResources.
  • enableSaveAs(Path) sets the folder the dialog opens in.
