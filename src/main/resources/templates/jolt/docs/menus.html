Available since 0.4.2. Four things that make a web page feel like a desktop program: a menu bar with keyboard shortcuts, a right-click menu that knows what was clicked, a global hotkey that works while another program has the focus, and printing the page to a PDF. All of them are built in Java, so the page needs no code. This page covers them in that order.

1. Menus and shortcuts

A Menu is built in Java, like a tray menu: actions, checkboxes, separators and submenus. A Shortcut is a key combination written the usual way:

Shortcut.parse("Ctrl+Shift+N")
  • Modifiers: Ctrl, Shift, Alt, Meta.
  • Keys: A to Z, 0 to 9, F1 to F24, Enter, Space, Tab, Escape, the arrows, Home, End, PageUp, PageDown, Insert, Delete, and punctuation such as , or Comma.
  • Anywhere a menu item takes a shortcut you can pass the text directly, as the next section does.

2. A menu bar

Give the window a native bar with setMenuBar:

window.setMenuBar(Menu.of(
        Menu.submenu("&File",                                           // & marks the letter that opens it with Alt; && is a real &
                Menu.action("&New window", "Ctrl+N", () -> newWindow()),
                Menu.action("&Open...", "Ctrl+O", () -> open()),
                Menu.separator(),
                Menu.action("E&xit", "Alt+F4", app::quit)),
        Menu.submenu("&View",
                Menu.check("&Dense list", dense, "Ctrl+D", on -> setDense(on)),   // the mark flips at once; on is the new state
                Menu.action("&Reload", "F5", () -> window.eval("location.reload()")))));
  • Menus are immutable. To tick a box or grey out an entry, build the menu again and call setMenuBar again. setMenuBar(null) removes the bar.
  • The window grows by the height of the bar, so the page area keeps the size you asked for.
  • Accelerators win over the page. While the page has the keyboard focus, the bar's shortcuts are handled before the page sees the key, so Ctrl+N does not also reach the page.
  • A frameless window has no place for a native bar, and supportsMenuBar() is false for it. Draw the menu in the page, or use a context menu.
  • On Windows the bar is drawn by the system, so it stays light in a dark app. Jolt does not hide it in full screen (not tested).

3. A context menu

By default a window has no right-click menu (or the web view's own one, if you created it with developer tools). setContextMenu shows a menu of yours instead. The provider is told what is under the pointer and returns a Menu, or null for none:

window.setContextMenu(info -> {
    if (info.isLink()) {
        return Menu.of(
                Menu.action("Open link", () -> app.openExternal(URI.create(info.linkUrl()))),
                Menu.action("Copy link", () -> app.clipboard().writeText(info.linkUrl())));
    }
    if (info.editable()) {
        return Menu.of(
                Menu.action("Cut",   "Ctrl+X", () -> window.edit(EditCommand.CUT)),
                Menu.action("Copy",  "Ctrl+C", () -> window.edit(EditCommand.COPY)),
                Menu.action("Paste", "Ctrl+V", () -> window.edit(EditCommand.PASTE)));
    }
    return null;
});
In infoMeaning
x, yThe position, in logical pixels.
pageUrlThe address of the page.
linkUrl, isLink()The link under the pointer.
sourceUrlThe image, audio or video under the pointer.
editableThe pointer is on a text field.
hasSelection, selectedTextWhether text is selected, and which. On Linux selectedText is empty: the system only says whether something is selected.
  • The web view works out what was clicked itself, so a page cannot claim a link is somewhere it is not.
  • window.edit(EditCommand) runs the commands a text field's menu offers (cut, copy, paste, undo, redo, select all) on whatever has the focus.
  • Pass null to setContextMenu to go back to the old behaviour. A page that draws its own menu in the DOM keeps working either way.
  • On Windows, WebView2 raises the right-click event only while its default menus are enabled, so Jolt enables them while a provider is set. Your menu always replaces theirs.

4. A global hotkey

A hotkey works whichever program has the focus: "press Ctrl+Alt+M to bring the app back" or "to start a quick capture".

if (app.supportsGlobalHotkeys()) {
    app.registerHotkey(Shortcut.parse("Ctrl+Alt+M"), main::focus)       // runs on the UI thread
       .whenComplete((hotkey, error) -> {
           if (error != null) log.warn("Ctrl+Alt+M is taken: {}", error.getMessage());
           // else keep `hotkey`, and call hotkey.close() to give the keys back
       });
}
  • It fails (the future completes with a JoltException) when another program already holds the combination. Offer the user a way to pick another one.
  • A combination with no Ctrl, Alt or Meta is refused with IllegalArgumentException, because it would take a plain letter away from every program. Function keys are the exception.
  • Windows only for now. On Linux supportsGlobalHotkeys() is false and registerHotkey throws UnsupportedOperationException: X11 would need key grabs, and Wayland offers nothing outside the desktop portals. Always check first.

5. Print and PDF

Turn the shown page into a PDF, or open the print dialog:

window.printToPdf(PrintOptions.defaults().withLandscape(true).withMargins(15))   // A4 or Letter by the user's country
      .thenAccept(pdf -> Files.write(Path.of("report.pdf"), pdf));               // the bytes of a PDF, no dialog

window.print();                                                                  // the web view's print dialog, like window.print()
  • The page is laid out for the paper, like a print, so @media print and @page rules in your CSS apply. That is how you hide buttons and sidebars from the PDF.
  • PrintOptions has landscape, scale, the paper (Paper, or any size in millimetres), margins, backgrounds and headerAndFooter (Windows only).
  • On Linux the page size, orientation and margins are honoured, and WebKit decides about the rest.
  • printToPdf fails with WindowClosedException if the window closes first. Write the file off the UI thread if it is large.
  • print() opens a dialog, so it is the one call here that automated tests cannot cover.
