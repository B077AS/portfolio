Available since 0.4.2. If your Java code is already a Spring Boot application, it can be the backend of a Jolt window: your beans, Spring Data repositories, validation and configuration stay as they are, and the window shows your page. The module is jolt-spring-boot-starter and it needs Spring Boot 4. This page shows the two ways the page can reach your beans and how the window and the Spring context start and stop together.

1. Add the starter

Add the starter next to jolt-core and the two backends from Getting started:

<dependency>
  <groupId>io.github.b077as</groupId>
  <artifactId>jolt-spring-boot-starter</artifactId>
  <version>0.5.0</version>
</dependency>

Then start the application with JoltSpringApplication instead of SpringApplication:

@SpringBootApplication
public class NotesApp {
    public static void main(String[] args) {
        JoltSpringApplication.run(NotesApp.class, args);
    }
}

That opens a native window and runs Spring behind it, in one process. The calling thread becomes Jolt's UI thread, and Spring starts on another thread at the same time, so the window and its web view are created while your beans are.

2. Two ways for the page to reach your beans

By default (jolt.mode=auto) the starter picks web when your application runs a servlet web server (Spring MVC) and rpc otherwise. You can set jolt.mode yourself.

3. rpc mode

Mark bean methods with @JoltRpc (io.github.b077as.jolt.JoltRpc, the same annotation Rpc.register uses, see annotated controllers). They answer jolt.call, and nothing listens on the network. Set spring.main.web-application-type=none if Spring MVC is on the class path anyway.

@Service
@JoltRpc("notes")                                    // optional prefix
class NotesService {
    @JoltRpc List<Note> list() { ... }               // jolt.call("notes.list")
    @JoltRpc Note add(NewNote note) { ... }          // jolt.call("notes.add", { text: "..." })
    @JoltRpc String export(Request r, RpcCall call) { call.progress(50); ... }
}
const notes = await jolt.call('notes.list');
await jolt.call('notes.add', { text: 'Buy milk' });
  • A method takes at most one parameter for what the page sends (decoded into its type, generics included), plus optionally the RpcCall and the calling WebWindow. It runs on a virtual thread and may return a CompletionStage, a Flow.Publisher or an RpcStream (streaming).
  • JSON is your application's own: its Jackson 3 ObjectMapper (Spring Boot 4's default), a Jackson 2 or Gson bean, or else JsonCodec.basic(). A JsonCodec, RpcOptions or Rpc bean of your own replaces the starter's.
  • Errors work as in RPC. An RpcException reaches the page with its code, and anything else only as internal, unless you say otherwise.
  • Inject Rpc anywhere to push events with rpc.emit(...).
  • Two methods with one name, or a name starting with jolt., stop the application at start-up with a message that names them.

Beans that join the Rpc

Available since 0.5.0. Instead of calling rpc.before or rpc.onException yourself, declare beans, as you would in any Spring application:

@Component
@Order(1)
class SignedIn implements RpcInterceptor {                  // wraps every call; @Order sets the order
    public Object intercept(RpcCall call, RpcHandler next) throws Exception {
        if (!session.isSignedIn()) throw new RpcException("unauthorized", "Please sign in");
        return next.handle(call);
    }
}

@Component
class SqlErrors implements RpcExceptionHandler<SQLException> {   // the exception type comes from the generic
    public RpcException handle(RpcCall call, SQLException e) { return new RpcException("sql", e.getMessage()); }
}

@Component
class MoreErrors {
    @JoltRpcExceptionHandler                                // like Spring's @ExceptionHandler
    RpcException invalid(IllegalArgumentException e) { return new RpcException("invalid", e.getMessage()); }
}

@JoltRpcExceptionHandler methods are checked at start-up: one exception parameter (optionally also an RpcCall), a return type of RpcException, and no two handlers for one exception type.

TypeScript declarations

Set jolt.rpc.typescript=frontend/src/jolt-api.d.ts and the starter writes the TypeScript declarations of your @JoltRpc methods at start-up. Methods are registered with their declared types, so they appear fully typed.

4. web mode

With Spring MVC the window shows your application's own server, so existing controllers, templates (Thymeleaf, JTE), htmx and static files work unchanged, and jolt.call works there too. The server listens on 127.0.0.1 on a free port, and only the window can use it:

  • The window first opens a one-time entry address. That sets an HttpOnly, SameSite=Strict session cookie in the window's own web view profile and redirects to jolt.web.start-path.
  • Every request without that cookie gets 403: other programs on the machine, and pages in the user's browser.
  • A Host that is not a loopback name (DNS rebinding) is refused, and so is a state-changing request from another Origin.

The guard is only there when the application is started by JoltSpringApplication, so a @SpringBootTest, or a plain run of the same application in a browser, is unaffected. WebFlux applications are not supported in web mode.

5. Start-up and shutdown

  • The window stays hidden until the page has loaded (jolt.window.show=on-load), so there is no white flash, and it appears after jolt.window.show-after (10 seconds) at the latest. With manual, the page calls jolt.call("jolt.window.show") itself.
  • If Spring fails to start, the window shows the error instead of vanishing.
  • Closing the window closes the Spring context, and closing the context (SpringApplication.exit) closes the window.
  • JoltRuntime, Application and WebWindow can be injected. JoltRuntime.whenShown() completes once the window is on screen, which is the moment to tell a jpack launcher.

6. Settings

In application.properties:

PropertyWhat it does
jolt.app-idThe application id (data folder, notifications).
jolt.modeauto (default), rpc or web.
jolt.uiThe page's files in rpc mode: classpath:ui (the default, src/main/resources/ui) or file:... for a folder while you develop.
jolt.window.*title, width, height, min-width, min-height, maximized, frameless, resizable, dev-tools, show, show-after.
jolt.web.start-pathWhere the window opens in web mode.
jolt.rpc.*expose-error-messages (shows every message while you develop), max-concurrent-calls, max-message-chars, stream-window, typescript.

The window settings are read before the beans exist, so they come from the environment. For anything else, such as an icon, a menu or a background colour, use the builder:

new JoltSpringApplication(NotesApp.class)
        .window(options -> options.withIcon(icon).withBackgroundColor(0x1E1E1E))
        .onWindow(window -> window.setMenuBar(menu))     // on the UI thread, before the page loads
        .run(args);

7. Good to know

  • Tested with real windows on Windows and on Linux (X11 and Wayland, headless): rpc mode, web mode with a request refused without the cookie, and a failed start shown in the window.
  • jolt.rpc.expose-error-messages=true registers a catch-all handler that shows every message. A handler of your own for Throwable replaces it.
  • Upgrading from 0.4.2: @JoltRpc moved from io.github.b077as.jolt.spring to io.github.b077as.jolt. Only the import changes. Beans are still found through proxies and composed annotations.
  • Package it like any Jolt app: see Packaging, and jpack to keep installs up to date.
