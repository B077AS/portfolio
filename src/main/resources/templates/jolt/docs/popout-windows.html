Available since 0.3.0. Many apps show one thing in a main window and open details in a second window: an email in its own window, a document in a new tab-like window, a settings panel. This page starts with plain multiple windows and then adds the safe way to let the page ask for one.

1. More than one window

app.createWindow(...) can be called as often as you like (on the UI thread, for instance from run or a message listener), and app.windows() lists the windows that are open. Each window is independent, with its own page and its own message listeners.

WebWindow second = app.createWindow(WindowOptions.defaults()
        .withTitle("Details")
        .withSize(700, 500)
        .withOwner(main));                  // stays in front of main and closes with it
second.loadResources(AppResources.classpath("ui"), router,
        ResourceOptions.defaults().withStartPath("/details/42"));
  • withOwner(window) makes a window belong to another one: it stays in front of it and closes with it.
  • ResourceOptions.withStartPath("/details/42") opens the window on that path of your app instead of index.html.
  • The app ends when the last window closes (unless you changed that in AppOptions).

2. Letting the page ask for a window

Often it is a click in the page that should open a window. The page never opens one itself: your Java code decides. You register an opener, a function that receives the request and either creates a window or refuses:

main.enableOpenWindow(app, request -> {                          // UI thread, once per request
    if (!request.path().startsWith("/message/")) return null;   // null refuses (the page gets false)
    WebWindow popout = request.createWindow(app);
    popout.loadResources(resources, router,
            ResourceOptions.defaults().withStartPath(request.path()));
    return popout;
});

Use request.createWindow(app) rather than app.createWindow: it turns the pop-out features on before the new page can load, so the new page can use jolt.openWindow and jolt.broadcast from its first line.

3. Ask from the page

const opened = await jolt.openWindow("/message/42", { key: "message-42", title: "Re: lunch", width: 900, height: 700 });
// true: a window opened, or the one with that key was brought to the front. false: the app refused.
  • key stops duplicates: asking again for the same key focuses the window that is already open (your opener is not called).
  • path must be an address inside the app (one leading /); //host, https://... and the like are rejected.
  • The window you return gets jolt.openWindow and jolt.broadcast too, with the same opener. Refuse inside the opener (look at request.opener()) if pop-outs must not open more windows. At most 10 requests per window per 10 seconds.
  • The request is yours to check: path, key, title and the sizes come from the page. request.options() has no owner; use .withOwner(request.opener()) if the pop-out should stay in front of its window and close with it.

4. Talking between windows

jolt.broadcast(text) goes to every other window that has called enableOpenWindow, and const stop = jolt.onBroadcast(text => ...) receives it. A window never gets its own broadcasts, and text is limited to 16 K characters. To refresh a message list after a reply, broadcast a short event such as "message-42:read" and let each window fetch what it needs.

// in the pop-out, after marking the message as read
jolt.broadcast("message-42:read");

// in the main window
const stop = jolt.onBroadcast(event => {
  if (event.endsWith(":read")) refreshList();
});

5. Window helpers in Java

  • window.isFocused() tells whether the window is the one the user is working in.
  • window.focus() brings a window to the front.
  • app.windows() lists all open windows.
