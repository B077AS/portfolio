In this tutorial you build a small notes app: type a note, add it to a list, delete it. It is tiny on purpose. The point is to see every piece of a Jolt app in one place: a Java class that owns the data, a page made of separate files, and a bridge between them. The code on this page was run on Windows against a real window.

You should have read Getting started and Messaging first. The tutorial uses the built-in Rpc that the messaging page introduces, with no extra library.

What we are building

  • The page shows an input, an Add button and the list. It knows nothing about storage.
  • The Java side keeps the notes and offers three functions: notes.list, notes.add, notes.remove.
  • The bridge is Jolt's built-in RPC: an Rpc in Java and jolt.call() in the page. There is no bridge code to write.

This is the same shape as a large app: swap the in-memory list for a database and the plain page for Vue or React, and nothing else changes.

Step 2: the data, in plain Java

Start with the part that has nothing to do with windows. A note is a record, and the store keeps a list of them:

package com.example.notes;

import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.concurrent.atomic.AtomicInteger;

public final class NoteStore {
    public record Note(int id, String text) {}

    private final List<Note> notes = new CopyOnWriteArrayList<>();
    private final AtomicInteger nextId = new AtomicInteger(1);

    public List<Note> list() { return List.copyOf(notes); }

    public Note add(String text) {
        if (text == null || text.isBlank()) throw new IllegalArgumentException("A note cannot be empty");
        Note note = new Note(nextId.getAndIncrement(), text.strip());
        notes.add(note);
        return note;
    }

    public void remove(int id) { notes.removeIf(n -> n.id() == id); }
}

The collections are thread-safe because Rpc runs each call on a virtual thread of its own, possibly at the same time. Throwing IllegalArgumentException for an empty note is how we will report a mistake to the page.

Step 3: the window and the bridge

package com.example.notes;

import io.github.b077as.jolt.*;

public final class NotesApp {
    record NewNote(String text) {}

    public static void main(String[] args) {
        NoteStore store = new NoteStore();
        Application app = Application.create(AppOptions.of("com.example.notes"));
        try {
            app.run(() -> {
                WebWindow window = app.createWindow(WindowOptions.defaults()
                        .withTitle("Notes").withSize(520, 640).withDevTools(true));

                Rpc rpc = Rpc.create()
                        .on("notes.list", call -> store.list())
                        .on("notes.add", NewNote.class, note -> store.add(note.text()))
                        .on("notes.remove", Integer.class, id -> { store.remove(id); return true; })
                        .onException(IllegalArgumentException.class,
                                (call, e) -> new RpcException("invalid", e.getMessage()));
                rpc.attach(window);                              // before the page loads

                window.loadResources(AppResources.classpath("ui"));
            });
        } finally {
            app.close();
        }
    }
}

Read it top to bottom: build the store, create the app, in run create a window, register three Java functions, attach them to the window, then show the files in ui.

  • NewNote is the shape of what the page sends to notes.add. Jolt turns the page's JSON into that record before your function runs. notes.remove gets just a number, so it asks for an Integer.
  • The onException line says that an IllegalArgumentException is an expected failure whose message is meant for the user. Without it, the page would only see a generic "internal" error, because Jolt never sends the text of unexpected exceptions to a page.
  • withDevTools(true) is there so you can inspect the page while learning; remove it for release.

Step 4: the page

Three small files in src/main/resources/ui.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Notes</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>Notes</h1>
  <form id="form">
    <input id="text" placeholder="Write a note" autocomplete="off">
    <button id="add">Add</button>
  </form>
  <p id="error" role="alert"></p>
  <ul id="list"></ul>
  <script type="module" src="app.js"></script>
</body>
</html>
body { font-family: system-ui, sans-serif; margin: 2rem auto; max-width: 28rem; }
form { display: flex; gap: .5rem; }
input { flex: 1; padding: .5rem; }
li { display: flex; justify-content: space-between; padding: .4rem 0; border-bottom: 1px solid #ddd; }
#error { color: #b00020; min-height: 1.2em; }
const list = document.getElementById('list');
const input = document.getElementById('text');
const error = document.getElementById('error');

function show(note) {
  const li = document.createElement('li');
  const span = document.createElement('span');
  span.textContent = note.text;                 // textContent, never innerHTML
  const del = document.createElement('button');
  del.textContent = 'Delete';
  del.onclick = async () => { await jolt.call('notes.remove', note.id); li.remove(); };
  li.append(span, del);
  list.append(li);
}

document.getElementById('form').addEventListener('submit', async event => {
  event.preventDefault();
  error.textContent = '';
  try {
    show(await jolt.call('notes.add', { text: input.value }));
    input.value = '';
  } catch (e) {
    error.textContent = e.message;
  }
});

(await jolt.call('notes.list')).forEach(show);

There is no bridge code: jolt.call(name, params) is already in the page and returns a promise. The file is all app:

  • Adding a note calls Java and shows what Java returns (including the id Java chose). If Java throws, the promise rejects with an error whose message is the text Java gave it, and that appears in the red paragraph.
  • The last line asks Java for the saved notes when the page starts. The page speaks first, so it is never too early for the answer.
  • Note text goes into the page with textContent. Setting innerHTML with text a user typed is how scripts get injected.

Step 5: run it

Run NotesApp with --enable-native-access=ALL-UNNAMED, as on the first page. Type a note and press Enter: it appears in the list. Press Add with an empty box: the error from your Java code shows in red. Delete removes a note.

Notes vanish when you close the window because they live in a list. Replacing NoteStore with one that writes a file in the app's data folder (AppOptions.dataDirectory()) or a database changes nothing in the page.

Where to go from here

  • Using TypeScript? Let Jolt write the types of notes.list and friends, so a typo in a call is a compile error.
  • Prefer a page that works like a small website, with forms and fetch? Serving files and requests builds this same app with a Router and no bridge code.
  • Want Spring beans, Spring Data and validation behind the page? Spring Boot.
  • Let the user export notes: file dialogs.
  • Remind the user about something: notifications.
  • Make it feel like your own app: window look, tray, and finally packaging.
