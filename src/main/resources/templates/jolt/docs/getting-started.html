Jolt opens a native window whose contents are a web page, and lets that page talk to your Java code in the same process. You write the interface in HTML, CSS and JavaScript and the logic in Java. It uses the web view the operating system already has, so there is no bundled browser and no native code to compile.

This page takes you from an empty folder to a running window in about ten minutes. You do not need to know anything about Jolt yet, only basic Java and a little HTML.

Requirements

  • JDK 25 and Maven 3.9 or newer (Gradle works too).
  • Windows 10 or 11 with the WebView2 Runtime (preinstalled on Windows 11).
  • Linux (X11 or Wayland) with GTK 3 and WebKitGTK 4.1: sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0.
  • A desktop session. A window needs a screen, so a plain server or container will not work.

macOS is not supported.

Step 1: create the project

Make a folder with a standard Maven layout:

hello/
  pom.xml
  src/main/java/com/example/hello/HelloApp.java

In pom.xml, add the API and both backends. Each backend only activates on its own operating system, so one jar runs on both.

<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.example</groupId>
  <artifactId>hello</artifactId>
  <version>1.0</version>

  <properties>
    <maven.compiler.release>25</maven.compiler.release>
    <jolt.version>0.4.1</jolt.version>
  </properties>

  <dependencies>
    <dependency>
      <groupId>io.github.b077as</groupId>
      <artifactId>jolt-core</artifactId>
      <version>${jolt.version}</version>
    </dependency>
    <dependency>
      <groupId>io.github.b077as</groupId>
      <artifactId>jolt-win32</artifactId>
      <version>${jolt.version}</version>
    </dependency>
    <dependency>
      <groupId>io.github.b077as</groupId>
      <artifactId>jolt-linux</artifactId>
      <version>${jolt.version}</version>
    </dependency>
  </dependencies>
</project>

Gradle:

implementation("io.github.b077as:jolt-core:0.4.1")
implementation("io.github.b077as:jolt-win32:0.4.1")
implementation("io.github.b077as:jolt-linux:0.4.1")

What each one is:

  • jolt-core is the API you write code against: Application, WebWindow and friends.
  • jolt-win32 and jolt-linux are the two backends. Jolt picks the one that matches the operating system at start-up and ignores the other.

Step 2: your first window

Create HelloApp.java:

package com.example.hello;

import io.github.b077as.jolt.*;

public class HelloApp {
    public static void main(String[] args) {
        Application app = Application.create(AppOptions.of("com.example.hello"));
        try {
            app.run(() -> {
                WebWindow window = app.createWindow(WindowOptions.defaults().withTitle("Hello").withSize(600, 400));
                window.onMessage(text -> window.postMessage("Java received: " + text));
                window.loadHtml("""
                        <button onclick="jolt.postMessage('ping')">Ping Java</button>
                        <p id="out"></p>
                        <script>jolt.onMessage(m => document.getElementById('out').textContent = m)</script>
                        """);
            });
        } finally {
            app.close();
        }
    }
}

Step 3: run it

Java must be started with --enable-native-access=ALL-UNNAMED. Jolt talks to the operating system through Java's foreign function API, and Java asks you to allow that explicitly. Without the flag the app still runs, but Java prints a warning on every start.

In IntelliJ IDEA or Eclipse, add it to the run configuration's VM options. From a terminal, build first, then run (PowerShell shown; on Linux use : instead of ; between class path entries):

mvn -q compile dependency:build-classpath "-Dmdep.outputFile=cp.txt"
java --enable-native-access=ALL-UNNAMED -cp "target\classes;$(Get-Content cp.txt)" com.example.hello.HelloApp

A 600 by 400 window titled "Hello" appears with one button. Click it: the page sends ping to Java, Java answers, and the answer appears under the button. You just crossed the bridge in both directions.

When you later package your app as a jar, put Enable-Native-Access: ALL-UNNAMED in the manifest (maven-jar-plugin, manifestEntries) and the flag is no longer needed. See Packaging your app.

What each line does

  1. AppOptions.of("com.example.hello") names your app. The id is also used for a per-user data folder (%LOCALAPPDATA%\com.example.hello on Windows, ~/.local/share/com.example.hello on Linux) where the web view keeps its storage.
  2. Application.create(...) finds the backend for this operating system.
  3. app.run(onStart) turns the calling thread into the UI thread and runs the window system's event loop. It blocks until the app ends: the last window closed, or app.quit(). The function you pass is called once, at the start, on that thread. Create your windows there.
  4. app.createWindow(options) opens the native window. WindowOptions.defaults() gives you a 1024 by 720 window; the with... methods return a changed copy (options are immutable, so you chain them).
  5. window.onMessage(listener) registers the Java side of the bridge. It is called with every message the page sends.
  6. window.postMessage(text) sends a message to the page.
  7. window.loadHtml(html) shows an HTML string. It is the quickest way to get something on screen. For real apps you will serve separate files; see Building the frontend.
  8. In the page, jolt is a global that Jolt adds to every page: jolt.postMessage(text) sends to Java and jolt.onMessage(callback) receives from Java.
  9. app.close() in finally releases the native resources, even if something threw.

To end the app, let main return rather than calling System.exit.

If it does not work

  • An error about the WebView2 runtime or GTK means a system component is missing; the troubleshooting page lists the messages and their fixes.
  • A window that opens but stays empty: developer tools are off by default, so create the window with .withDevTools(true), right-click and choose Inspect, then read the console.
