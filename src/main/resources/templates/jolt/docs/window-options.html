The operating system draws the window's frame, title bar and icon, so you set them from Java, either when you create the window or later. This page goes from the options every app sets, to controlling where and when the window appears, to drawing your own title bar, either from scratch or with the ready-made one, and finally to full screen and Windows 11 snap layouts.

1. The basics

WindowOptions is immutable: start from defaults() (title "Jolt", 1024 by 720) and chain with... calls, each of which returns a changed copy.

WebWindow window = app.createWindow(WindowOptions.defaults()
        .withTitle("Parsel")
        .withSize(1200, 780)
        .withMinSize(600, 400)               // smallest size the user can drag to
        .withIcon(iconBytes));               // multi-size .ico (best) or PNG

Most of these can also be changed on a live window: window.setTitle(...), setSize(w, h), setIcon(bytes).

Load the icon from your resources, for example:

byte[] iconBytes;
try (InputStream in = MyApp.class.getResourceAsStream("/icon.ico")) {
    iconBytes = in.readAllBytes();
}
  • Use an .ico with 16, 24, 32, 48 and 256 px images: Windows picks the matching size instead of scaling one bitmap. On Linux the largest image is used.

2. Colours and theme

If your app is dark, tell the window, so its title bar matches and nothing flashes white while the page loads:

WindowOptions options = WindowOptions.defaults()
        .withTitleBarScheme(ColorScheme.DARK)    // or LIGHT
        .withBackgroundColor(0x0F1117);          // behind the page until it paints: no white flash

window.setTitleBarColors(0xF4F5FA, 0x1A1D29);    // exact colours (background, text), Windows 11 only

3. Where and when the window appears

WindowOptions options = WindowOptions.defaults()
        .withMaximized(false)
        .withCentered(true)                      // the default
        .withVisible(false);                     // call window.show() when the page is ready

window.maximize(); window.restore(); window.isMaximized();
window.hide(); window.show(); window.minimize(); window.isMinimized();
  • Start hidden and call show() when the page sends "ready", so the window appears with its content already drawn (see Building the frontend).
  • On Wayland the compositor decides placement, so withCentered is ignored and the icon comes from the app's .desktop file. Jolt names the process after your app id, which is what lets the compositor find it.
  • On Wayland there is no signal when a window is minimized, so Jolt records the minimize itself: isMinimized() is true after minimize() and goes back to false when the window gets the keyboard focus again (fixed in 0.4.1).
  • AppOptions.of(id).withQuietNativeLogs(true) hides GTK's known harmless warnings on Linux.

4. Frameless windows

Available since 0.3.0. WindowOptions.defaults().withFrameless(true) removes the operating system's title bar and border, so the page draws its own. That gives you full control of the look, at the price of providing the title bar's behaviour yourself:

<header data-jolt-drag>                       <!-- drag here to move the window; double-click maximizes or restores -->
  <span>Parsel</span>
  <button onclick="jolt.frame.minimize()">–</button>
  <button onclick="jolt.frame.toggleMaximize()">☐</button>
  <button onclick="jolt.frame.close()">✕</button>
</header>
  • data-jolt-drag marks the draggable area. Buttons, links and form fields inside it keep working; add data-jolt-no-drag to exclude anything else. (CSS app-region: drag is not used, because WebKitGTK does not support it.)
  • The window can be resized from thin invisible handles along its edges and corners, which Jolt adds to the page.
  • jolt.frame.close() closes the window as the close button would, so setCloseBehavior(HIDE) applies to it too.
  • On Windows the window keeps its sizing frame, which lets Windows draw the shadow and snap it (Win+arrows). Linux snaps as your window manager does.
  • Frame commands only work on windows created frameless, and only for pages the SecurityPolicy trusts.
  • This works with loadHtml and loadResources alike.

5. A ready-made title bar

Available since 0.4.0. Writing the buttons yourself (section 4) gives total control, but most apps just want working minimize, maximize and close buttons in their own colours. Mark any element with data-jolt-titlebar and Jolt does the rest:

<style>
  header { display: flex; align-items: center; height: 32px; padding-left: 12px;
           background: #161616; color: #ddd;
           --jolt-caption-hover-bg: #2a2a2a;      /* hover colour of minimize and maximize */
           --jolt-close-hover-bg: #e5484d;        /* the close button; red by default */
           --jolt-maximize-fg: #7aa2f7; }         /* one button on its own */
</style>
<header data-jolt-titlebar><span>Parsel</span></header>
  • The bar moves the window, and the minimize, maximize/restore and close buttons are added at its right end. Make the bar display: flex so your own content and the buttons sit side by side.
  • For a dialog that should only have a close button, use data-jolt-titlebar="close".
  • The buttons live in a shadow root, so your page CSS cannot break them by accident. You style them through the custom properties below.
  • Your own markup with jolt.frame.minimize() and friends keeps working as before; the kit is optional.
Custom propertySets
--jolt-caption-fg, --jolt-caption-bgIcon and background colour of all buttons.
--jolt-caption-hover-fg, --jolt-caption-hover-bgColours while the pointer is over a button.
--jolt-caption-active-fg, --jolt-caption-active-bgColours while a button is pressed.
--jolt-caption-widthWidth of each button (default 46px).
--jolt-caption-iconSize of the icon (default 10px).
--jolt-caption-inactive-opacityHow faded the buttons are while the window is not in front (default .55).
--jolt-minimize-*, --jolt-maximize-*, --jolt-close-*The same fg, bg, hover and active set for one button. The specific one wins over --jolt-caption-*.

Because these are ordinary custom properties, a light and a dark theme is a few lines in a prefers-color-scheme rule.

6. The page knows its window's state

Available since 0.4.0. A custom title bar has to look different when the window is maximized (no rounded corners) or not in front (dimmed). Jolt keeps these attributes on <html> up to date, with or without the kit:

AttributePresent when
data-jolt-maximizedThe window is maximized.
data-jolt-inactiveThe window is not the one in front.
data-jolt-fullscreenThe window is full screen (next section).
data-jolt-platform="windows" or "linux"Always, so you can style per system.
 
<style>
  header { border-radius: 8px 8px 0 0; }
  html[data-jolt-maximized] header { border-radius: 0; }       /* square corners when maximized */
  html[data-jolt-inactive] header { opacity: .7; }             /* dim when not in front */
</style>

From script, ask or subscribe:

jolt.frame.isMaximized();                    // true or false
jolt.frame.isFocused();
const stop = jolt.frame.onChange(({ maximized, focused, fullscreen }) => {
  maximizeIcon.textContent = maximized ? 'restore' : 'maximize';
});
// stop();   // stop listening

7. Full screen

Available since 0.4.0. A video player, a presentation or a game wants the whole screen, with no title bar, border or taskbar. The browser's F11 stays disabled in a Jolt window, so this is how you do it:

window.setFullscreen(true);
window.isFullscreen();            // updated on the UI thread: right after setFullscreen it may still say the old value
window.setFullscreen(false);      // back to the size, position and maximized state it had

A frameless page can do the same itself:

jolt.frame.setFullscreen(true);
jolt.frame.toggleFullscreen();
jolt.frame.isFullscreen();
  • While it is on, <html> has data-jolt-fullscreen and the resize handles are hidden. Use the attribute to hide your own title bar: html[data-jolt-fullscreen] header { display: none }.
  • A window that is still hidden (withVisible(false)) is full screen when first shown.
  • Windows places the window over the monitor, taskbar included. Linux uses gtk_window_fullscreen, which needs a window manager or compositor that honours it.
  • Give the user a way out, for example a key such as Esc that leaves full screen.
  • Interface change in 0.4.0: WebWindow gained two abstract methods, setFullscreen and isFullscreen. Only code that implements WebWindow itself is affected.

8. Windows 11 snap layouts and the window menu

Available since 0.4.0. On Windows 11, resting the pointer on a maximize button shows the snap layouts flyout. A web page cannot do that on its own, because Windows only shows it over a native maximize button. Jolt makes it work for yours:

<button data-jolt-maximize onclick="jolt.frame.toggleMaximize()">☐</button>

<style>
  [data-jolt-maximize]:hover,
  [data-jolt-maximize][data-jolt-hover] { background: #2a2a2a; }     /* style hover both ways */
  [data-jolt-maximize][data-jolt-pressed] { background: #3a3a3a; }
</style>
  • The kit's maximize button does all this by itself. For your own button, mark the element with data-jolt-maximize.
  • Jolt reports the button's position to the window, which puts a nearly invisible child window over it that answers like a native maximize button. The page then no longer receives the pointer over that spot, so Jolt sets data-jolt-hover and data-jolt-pressed on your element instead. Style both :hover and [data-jolt-hover], or the button looks dead on Windows 11.
  • Clicks still maximize through the window itself.
  • On Windows 10 and Linux nothing is added and the button is an ordinary button. Linux has no snap layouts.

Also on Windows, right-clicking a title bar (a data-jolt-drag or data-jolt-titlebar area) opens the system window menu: Restore, Move, Size, Minimize, Maximize, Close. jolt.frame.menu() opens it from code, for example from an icon in the corner. Frameless windows are also rounded explicitly on Windows 11. Linux has no window menu on right click, and whether frameless windows get a shadow or rounded corners there depends on the window manager.
