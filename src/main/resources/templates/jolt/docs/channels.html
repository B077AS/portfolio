Messages are text. To send big or binary data, such as video frames, images and files, you could encode it as base64 inside JSON, but that makes it a third larger and costs time on both ends. A channel is a named two-way pipe that carries raw bytes instead: no base64 and no JSON. Available since 0.2.3.

Reach for a channel when you move more than a few hundred kilobytes, or many frames per second. For everything else, messages are simpler.

1. Open a channel

Give the channel a name on the Java side, before the page loads, and use the same name in the page:

BinaryChannel bytes = window.openChannel("bytes");
bytes.onOpen(() -> bytes.send(ByteBuffer.wrap(new byte[] {1, 2, 3, 4, 5})));
bytes.onMessage(data -> System.out.println("Java got " + data.remaining() + " bytes"));

window.loadResources(AppResources.classpath("ui"));
const bytes = jolt.channel("bytes");
bytes.onMessage(data => {                          // an ArrayBuffer
  console.log(data.byteLength, new Uint8Array(data));
  bytes.send(new Uint8Array([9, 9]));              // back to Java
});

Run it and the page receives the 5 bytes 1,2,3,4,5 and Java receives the 2 bytes the page sends back. Channel names starting with jolt. are reserved.

2. Behaviour

  • The page connects and reconnects by itself. onOpen, onClose and isOpen() tell you the state. Send from onOpen (as above) when you want data the moment the page is connected.
  • send never blocks and returns false if no page is connected, the channel is closed, or the page is too far behind to take more.
  • Callbacks run on a thread of their own, not the UI thread.
  • Messages arrive as ByteBuffer in Java and ArrayBuffer in the page, and the page can send an ArrayBuffer, a typed array such as Uint8Array, or a string. You can also send a byte[] directly from Java.

3. Live data: keep only the newest

If Java produces frames faster than the page can draw them, a queue would grow and the picture would lag further and further behind. Ask for newestOnly and a slow page just skips old frames:

BinaryChannel video = window.openChannel("video", ChannelOptions.newestOnly());
video.send(ByteBuffer.wrap(jpegBytes));        // call as often as you like

ChannelOptions.defaults().withMaxQueuedBytes(...) and withMaxMessageBytes(...) set limits for the normal queueing mode (defaults: 16 MB queued, 64 MB per message).

4. How it is protected

  • A channel is a WebSocket on 127.0.0.1, accepted only from origins your SecurityPolicy trusts and with a per-run secret.
  • On Linux, use loadResources (not loadHtml) for pages that open channels.
  • Closing a channel, or its window, no longer waits for a page that stopped reading. The close frame is given 250 ms and the connection is then closed regardless (fixed in 0.4.1).
  • On Windows, version 0.4.1 also fixed large messages that could stop part way (about 40% of 2 MB messages in tests, caused by a lost wakeup in the JDK's socket poller). If you saw a channel hang on big frames with an older version, update.
