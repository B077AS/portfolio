Most start-up problems come from a missing system component, and most later problems from one of three habits: blocking the UI thread, using absolute URLs, or loading a page the security policy does not trust. These are the common symptoms and what fixes them.

Symptoms

SymptomLikely cause
WebView2 Runtime is not installedInstall the WebView2 Runtime (Windows).
GTK 3 / WebKitGTK 4.1 could not be loadedInstall libgtk-3-0 and libwebkit2gtk-4.1-0.
GTK could not open a displayNo DISPLAY or WAYLAND_DISPLAY: a server or container without a display.
Warning about native access at startAdd --enable-native-access=ALL-UNNAMED.
Could not find or load main class .url=...PowerShell split -Dui.url=... at the dot. Quote it.
Window stays blankOpen developer tools and read the console. With loadUrl, check the dev server is running and that its origin is trusted.
Page loads but its CSS/JS/images are missing (404)The folder name in AppResources.classpath("ui") does not match src/main/resources/ui, or the page uses absolute URLs. Use relative ones such as style.css.
jolt is not definedThe page is not running inside the Jolt window (for example it was opened in a normal browser through a fixed loopback port), or it runs in a frame, where the bridge is off by default.
call(...) never resolvesYour handler never replied, or the page was reloaded.
Nothing arrives in onMessageThe page's origin is not trusted by the SecurityPolicy. Add a window.onBlocked listener and look for MESSAGE or NAVIGATION events.
The window freezesSomething slow ran in a message listener. Move it to a worker thread.
A link or target=_blank does nothingThe security policy blocks it. Handle it in onBlocked, for instance with app.openExternal.
The tray icon is missing on LinuxThere is no tray host. app.isTraySupported() is false on stock GNOME without the AppIndicator extension.
No notification appearsThe future from app.notify says false: notifications are turned off, or on Linux there is no notification service.
getUserMedia fails with NotAllowedErrorPermissions are refused by default. Grant them for your own pages with withGrantedPermissions(Permission.MICROPHONE, Permission.CAMERA). See Security. getDisplayMedia is not covered.
Clipboard.onChange never fires for what the user copies in other programs (Linux)On Wayland GTK 3 does not report clipboard changes made by other programs. Your own writes are still announced. See Clipboard.
readFiles() is empty although FILES is reported (Linux)The clipboard holds a text/uri-list, which browsers also offer for plain links. Check the result.
Dropping a file replaces the app with the fileNo onFileDrop listener is registered. Register one before the page loads. See Dragging files.
onFileDrop never firesThe page is not trusted by the SecurityPolicy, or on Windows the WebView2 Runtime is too old to support postMessageWithAdditionalObjects.
The myapp:// link does nothingThe scheme was not registered (not from a development run, see Custom links), or the link is only read in main and not in the SingleInstance callback.
The taskbar progress bar or buttons do not showButtons are Windows only, and appear once the window has been shown. On Linux progress needs KDE Plasma, Ubuntu's dock or Dash to Dock and an installed <appId>.desktop file. Check supportsTaskbarProgress() and supportsTaskbarButtons().
setTaskbarButtons throws IllegalArgumentExceptionWindows fixes the number of buttons at the first call. Give the maximum up front and use fewer later.
The jump list is missing or sits on Java's icon (Windows)The appId has spaces or is over 128 characters, so no list is made. Categories are also hidden if the user turned off "Show recently opened items".
The snap layouts do not show over my maximize buttonWindows 11 only. Mark the element data-jolt-maximize or use data-jolt-titlebar, and the window must be frameless.
My maximize button looks unpressed on Windows 11The page does not get the pointer there. Style [data-jolt-hover] and [data-jolt-pressed] as well as :hover.
Ctrl+F, F5 or zoom keys do nothing (Windows)Browser shortcuts are disabled in the web view. Build the feature in the page.
Old icon in the taskbarWindows caches it. Unpin and re-pin, or restart Explorer.

Looking inside

  • Create the window with .withDevTools(true) and use Inspect for the console, network and elements of the page.
  • Handler exceptions never reach the page, only a bare 500; the details are in your application log. For messages, an exception in an Rpc function comes back as the rejected promise's message.
  • On Linux, AppOptions.of(id).withQuietNativeLogs(true) hides GTK's known harmless warnings so real ones stand out.
